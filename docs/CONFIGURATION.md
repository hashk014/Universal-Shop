# Configuration

The generated `config.yml` controls the economy, taxes, rotation, promotion and marketplace. `shops.yml` holds all products. Validate changes with `/shop admin reload`; invalid reloads preserve the last working configuration in memory. Admin item/price edits validate the catalog and save `shops.yml.bak` before replacing the file.

See [command switches and Bedrock setup](BEDROCK-AND-COMMANDS.md) for `disabled-commands`, `/shop admin command`, and `bedrock.enabled`. Upgrading from 1.0.0 preserves existing files; omitted new options use their defaults (no disabled commands, native Bedrock forms enabled).

See [optional management modules](MANAGEMENT.md) for the `management` section introduced in 1.2.0: all nine modules are off by default, and `/shop admin panel` provides module toggles. Examples cover schedules, product quotas, budgets, targeted campaigns, loyalty, protected sales and personal preferences.

## A complete product

```yaml
products:
  diamond:
    name: Diamond
    category: Resources
    material: DIAMOND
    buy: 200.00
    sell: 65.00
    permission: universalshop.diamonds
    worlds: [world, resource_world]
    stock: 256
    restock-hours: 168
    daily-buy-limit: 32
    daily-sell-limit: 64
    dynamic:
      enabled: true
      step: 0.01
      min: 0.6
      max: 2.5
    rotating: true
    rotation-only: false
```

| Field | Meaning |
| --- | --- |
| Product ID | 1–48 lowercase letters, digits, `_` or `-`; keep stable to retain stock/limits |
| `name`, `category` | Display name and category; `&` color codes supported in names |
| `material` | Bukkit material; `OAK_PLANKS\|WOOD` gives modern/legacy aliases |
| `data` | Optional legacy durability/data value; default 0 |
| `item` | Bukkit-serialized exact item, generated by `/shop admin add` |
| `buy`, `sell` | Price **per individual item**; `-1` disables that direction; zero allows free trade |
| `permission` | Additional permission required to view and trade this product |
| `worlds` | Allowed worlds; omitted/empty means all otherwise-enabled worlds |
| `stock` | `-1` for unlimited, otherwise a capacity/current initial amount |
| `restock-hours` | Restore finite stock to capacity every interval; `0` disables automatic restocking |
| `daily-buy-limit`, `daily-sell-limit` | Number of items per UUID per UTC day; `0` means unlimited |
| `dynamic.enabled` | Enable demand-based prices |
| `dynamic.step` | Multiplier change per net item purchased |
| `dynamic.min`, `dynamic.max` | Lower/upper multiplier bounds |
| `rotating` | Eligible for the featured selection |
| `rotation-only` | Visible/tradable only while selected; requires `rotating: true` |
| `commands` | Console delivery commands; replaces item delivery and prohibits selling |

Selling restores finite stock up to its capacity; it does not create over-capacity stock. Restocks affect stock, not historical demand. Finite stock is global to this single server. All daily limits are shared between GUI, commands and bulk sales.

When aliases are used, write modern names first and legacy names last. A material that does not exist on the current server is skipped with a warning. A malformed supported product fails validation. Only use item materials, not crops/block-only enum values. `CARROT|CARROT_ITEM` and `POTATO|POTATO_ITEM` handle the historical crop/item naming difference.

## Custom items

Hold the finished item and run:

```text
/shop admin add explorers_pickaxe 500 -1 Adventure
```

The plugin saves an amount-one template and preserves metadata using Bukkit item serialization. It does not flatten items into only a material name. Selling checks `ItemStack.isSimilar`: names, enchantments, damage and custom data matter. Ordinary diamonds will not consume an enchanted/named diamond stack.

Modern custom item data is subject to Minecraft's own version support. Do not downgrade a live world or expect a modern serialized item to work on a server predating its components. Capture separate version-appropriate templates when distributing a catalog across different server generations.

## Services, keys and ranks

Example for experience delivery:

```yaml
products:
  experience:
    name: 20 Experience Points
    category: Services
    material: EXPERIENCE_BOTTLE|EXP_BOTTLE
    buy: 50
    sell: -1
    daily-buy-limit: 5
    commands:
      - 'xp 20 {player}'
```

Command products deliver **commands instead of the icon item**. They are bought one at a time. `{player}` expands to the online player's name and `{uuid}` to their UUID. Use the documented command syntax of your installed rank, key, permission or other plugin. Commands run as console, so only trusted administrators should edit this file. Do not accept arbitrary commands from players.

If a command reports dispatch failure, or delivery throws after the transaction was prepared, trading locks. See [OPERATIONS.md](OPERATIONS.md). Some plugins report success despite rejecting an action internally; test their commands before charging players for them.

## Deals and promotions

Rotation is deterministic for a given seed, eligible catalog and interval. It survives restarts without rerolling. The default interval is 168 hours; use 24 for daily deals. Intervals are aligned to the Unix epoch in UTC, not to the first startup or a local Monday. `/shop deals` displays the next rotation timestamp in UTC.

The highest applicable discount wins; discounts do not stack. A discounted buy price cannot fall below that product's corresponding sell value. A scheduled sale uses UTC ISO-8601 timestamps:

```yaml
promotion:
  starts: '2026-12-20T00:00:00Z'
  ends: '2026-12-27T00:00:00Z'
  discount-percent: 10
permission-discounts:
  universalshop.vip: 5
```

Prices are rounded conservatively per item: purchases up and sales down to a cent. Dynamic pricing uses the marginal demand level for each item; bulk and split orders therefore agree when other conditions do not change. This protects immediate buy/sell loops within one product. Administrators remain responsible for crafting recipes, duplicate product templates, cross-plugin trades and long-term market arbitrage.

## Permissions

| Permission | Default |
| --- | --- |
| `universalshop.use` | Everyone |
| `universalshop.buy` | Everyone |
| `universalshop.sell` | Everyone |
| `universalshop.market` | Everyone |
| `universalshop.pay` | Everyone |
| `universalshop.admin` | Operators |
| `universalshop.vip` | Nobody; assign explicitly for the example discount |

Product permissions are additional checks. Creative-mode trading is disabled. `disabled-worlds` applies to trading and shop navigation. Use a permissions plugin to adjust access.

## Marketplace

The held item identifies an exact template, and the requested quantity is collected from all 36 storage slots. Items are removed into escrow when the listing is created. The buyer pays the listing's **total** price, and the seller receives it minus market tax, even while offline. Expired listings remain reclaimable by their owners and count toward the listing limit until canceled. They are not automatically dropped or mailed, so a full inventory cannot lose returned items.

The marketplace is only available in internal economy mode. Server shop stock and rotating deals are independent of player listings.
